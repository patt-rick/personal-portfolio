FibreLink

September 2026 – now · v1.1.0

Download ↗

FibreLink gives a household simple control over who uses the home internet and when. It groups phones, tablets and laptops by person, pauses them at bedtime or homework time or once they hit a daily or monthly data limit, blocks websites, manages the router's Wi-Fi networks and shows who used how much. It runs on a PC in the home and talks to a Huawei fibre router over the local network. No household data leaves the house.

There's a Node and Fastify engine that signs in to the router, enforces the rules and samples usage into SQLite, and a React dashboard that opens on the PC or on any phone on the home Wi-Fi, where it installs as a PWA. On Windows it ships as an installer: the engine runs as a service, so it keeps enforcing with nobody signed in, and a Tauri tray app shows status and sends notifications. I started it in September 2026; it's at v1.1.0 after 265 commits.

Talking to the router without a browser

Huawei's ONTs have no API, only a web UI. That UI turns out to ship its data as inline JavaScript globals (the device list, Wi-Fi networks, MAC filters and parental-control templates), so FibreLink reads those as text over plain HTTP and posts the same forms the pages submit. The whole family of Huawei ONT web UIs shares those pages, so it should work on most models unmodified. The first driver steered a headless browser with Playwright; the HTTP driver is the one that ships.

The router does most of the enforcing

Schedules and site blocks are written into the router's own parental-control templates and bound to each device's MAC address, and a pause adds the device to the Wi-Fi MAC filter. So most schedules and all site blocks keep holding while the PC is off. Data limits, pausing by hand and the few schedules the router can't fit run from the engine instead. The app's database is the source of truth: on startup and on a timer it reads the router back and corrects any drift.

Usage by person

This hardware can't meter single devices, but it does count bytes per Wi-Fi network. So a person or group gets their own network, and the engine credits each slice of traffic to whoever owned that network at the time. Wired devices and the main network can't be split this way, and the dashboard shows that leftover as its own figure instead of hiding it.

  • Node.js
  • Fastify
  • SQLite
