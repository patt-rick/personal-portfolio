Terminal Workspace

June 2026 – now · v0.6.0

Code

Terminal Workspace is a desktop app for juggling many projects at once, each with as many terminals as it needs. It's built for working alongside coding agents like Claude Code, aider and Codex, but any shell is welcome.

I built it in Rust and Tauri 2, starting in June 2026, with an interface of its own. It's now about 250 commits and roughly 20,000 lines of Rust.

What it does

  • Terminals keep running when you switch projects, with bell and “working” indicators so you know which agent needs you.
  • Claude hooks can send a push notification to your phone when a session wants attention.
  • Browse and resume past Claude Code sessions, switch between Claude accounts, and see usage and cost.
  • API keys live in the OS keychain and are injected into terminals as environment variables.
  • A file tree with quick open, a CodeMirror editor, a git diff viewer, and per-repo GitHub push identities.
  • Six themes, WSL support and signed auto-updates.

Closing a terminal means closing everything in it

On Windows, killing a shell doesn't kill the dev server it started. So each shell runs inside a Windows Job Object: when the terminal closes, the whole process tree goes with it and nothing is left holding a port. The app also ships its own newer ConPTY build next to the binary rather than relying on the one that comes with Windows.

Your terminals, from your phone

An embedded axum server can be reached through a Cloudflare quick tunnel or Tailscale. Pairing uses a six-digit code that expires after five minutes and locks after five wrong tries, then hands the phone a 256-bit session token that only ever lives in memory. Every remote action goes through an explicit allowlist, and push notifications use Web Push encryption implemented directly on ring. The phone client is a single HTML file compiled into the binary.

The “working” indicators come from OSC 133 shell-integration markers, which tell the app exactly when a command starts and finishes.
